`addSubform` attaches another `AdvancedFormController` as a child. Its fields join the parent's `validate`,
`resetAll`, `markReadOnly`, `clearErrors`, `setValidationMode`, `setValidationEnabled` and every other broadcast, and
they count towards the parent's `wasModified`, `canSubmit`, `validating` and `validationErrors`. Use subforms to split a
large form into readable pieces, for sections that appear dynamically, and for wizards.

```dart
class CheckoutFormController extends AdvancedFormController {
  CheckoutFormController() {
    registerFields([email]);
    addSubform(shipping); // its fields are now part of this form
  }

  final email = AdvancedTextFieldController(validator: filled(MyError.required));
  final shipping = ShippingFormController(); // another AdvancedFormController
}
```

## A dynamic list

Every guest below is its own `AdvancedFormController`, attached when added and detached when removed. The parent's
`validate()` walks every attached one.

<AdvancedFormsExample preview="GuestListForm" title="guest_list.dart">

```dart title="guest_list_controller.dart"
class GuestController extends AdvancedFormController {
  GuestController() {
    registerFields([name, email]);
  }

  final name = AdvancedTextFieldController(validator: filled('Name required'));
  final email = AdvancedTextFieldController(
    validator: (value) => value.contains('@') ? null : 'Not an email',
  );
}

class GuestListController extends AdvancedFormController {
  GuestListController() {
    addGuest();
  }

  // Navigation state of our own: which subforms are on screen, in order.
  // AdvancedFormState.subforms is a Set and knows nothing about order.
  final guests = <GuestController>[];

  void addGuest() {
    final guest = GuestController();
    addSubform(guest);
    guests.add(guest);
    notifyListeners();
  }

  void removeGuest(GuestController guest) {
    // Detaches only. The parent still owns it and disposes it with itself.
    removeSubform(guest);
    guests.remove(guest);
    notifyListeners();
  }
}
```

```dart title="guest_list_form.dart"
class GuestListForm extends StatefulWidget {
  const GuestListForm({super.key});

  @override
  State<GuestListForm> createState() => _GuestListFormState();
}

class _GuestListFormState extends State<GuestListForm> {
  final _form = GuestListController();

  @override
  void dispose() {
    _form.dispose(); // disposes every guest, attached or not
    super.dispose();
  }

  Future<void> _invite() async {
    final ok = await _form.validate();
    if (mounted) {
      ExampleLog.of(
        context,
      ).add(ok ? 'Invited ${_form.guests.length} guest(s).' : 'Fix the list.');
    }
  }

  @override
  Widget build(BuildContext context) {
    // Rebuilds when guests are added or removed (notifyListeners above).
    return ListenableBuilder(
      listenable: _form,
      builder: (context, _) => Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        children: [
          for (final (index, guest) in _form.guests.indexed)
            _GuestCard(
              key: ObjectKey(guest),
              index: index,
              guest: guest,
              onRemove: _form.guests.length > 1
                  ? () => _form.removeGuest(guest)
                  : null,
            ),
          DocsActions(
            children: [
              OutlinedButton.icon(
                onPressed: _form.addGuest,
                icon: const Icon(Icons.add, size: 18),
                label: const Text('Add guest'),
              ),
              DocsSubmitButton(
                form: _form,
                label: 'Invite',
                onPressed: _invite,
              ),
            ],
          ),
        ],
      ),
    );
  }
}

class _GuestCard extends StatelessWidget {
  const _GuestCard({
    super.key,
    required this.index,
    required this.guest,
    required this.onRemove,
  });

  final int index;
  final GuestController guest;
  final VoidCallback? onRemove;

  @override
  Widget build(BuildContext context) {
    return Card(
      margin: const EdgeInsets.only(bottom: 10),
      child: Padding(
        padding: const EdgeInsets.fromLTRB(14, 4, 6, 8),
        child: Column(
          children: [
            Row(
              children: [
                Text(
                  'Guest ${index + 1}',
                  style: Theme.of(context).textTheme.labelLarge,
                ),
                const Spacer(),
                IconButton(
                  onPressed: onRemove,
                  icon: const Icon(Icons.close, size: 18),
                  tooltip: 'Remove',
                ),
              ],
            ),
            DocsTextField(field: guest.name, label: 'Name'),
            DocsTextField(field: guest.email, label: 'Email'),
          ],
        ),
      ),
    );
  }
}
```

## Attaching, detaching, owning

- **`addSubform(form)`** attaches. A no-op if already attached. The parent applies its validation mode to the subform
  at once — unless the subform has a mode of its own.
- **`removeSubform(form)`** detaches: the subform stops validating, notifying and counting towards the parent's state,
  and can be re-attached later. It does **not** dispose it.
- **The parent owns every subform it was ever given** and disposes them all in its own `dispose()`, attached or
  detached — the same way it owns registered fields. Do not dispose subforms yourself. If you do anyway, the parent
  skips them rather than disposing them twice.
- **Ownership is single-parent.** A subform attached to two parents is not supported.
- Calling `addSubform` with — or on — a disposed controller throws a descriptive `StateError`, and so do
  `registerFields`, `removeSubform` and `setValidationEnabled` on a disposed form. A disposed controller cannot be
  reused; build a fresh one per appearance.

Both membership changes recompute `wasModified`, so attaching an already-modified subform marks the parent modified at
once, and removing the only modified child clears the flag.

### Detach, or switch validation off?

A section that is *visible but not applicable* is better kept attached with `setValidationEnabled(false)`: its errors
are cleared, its fields leave `canSubmit`, `validating`, `hasFailedValidation` and `validationErrors`, its `validate()`
returns `true` without running, and everything else — `resetAll`, `markReadOnly`, disposal — still reaches it.
Switching back on re-runs the sync validators at once. Detach when the section genuinely leaves the screen and its
values should not survive.

## A wizard, validated step by step

One subform per step is what makes per-step validation one line: `await step.validate()` reaches that step's fields and
nothing else, so a field on a later step is never flagged before the user gets there. The final submit calls the
parent's `validate()`, which walks every attached step, so a step the user walked back over is checked again.

<AdvancedFormsExample preview="WizardForm" title="wizard.dart" code="collapsed">

```dart title="wizard_steps.dart"
/// One step of the wizard: an ordinary form controller with a title.
abstract class WizardStep extends AdvancedFormController {
  String get title;
}

class AccountStep extends WizardStep {
  AccountStep() {
    registerFields([email, password]);
  }

  @override
  String get title => 'Account';

  final email = AdvancedTextFieldController(
    validator: (value) => value.contains('@') ? null : 'Enter an email',
  );
  final password = AdvancedTextFieldController(
    validator: atLeastLength(8, 'At least 8 characters'),
  );
}

class AddressStep extends WizardStep {
  AddressStep() {
    registerFields([country, city]);
    // Picking another country clears the city — a relation, not a rule.
    addRelation(country, (value) => value, (_) => city.reset());
  }

  @override
  String get title => 'Address';

  final country = AdvancedSingleSelectFieldController<String, String>(
    initialValue: null,
    options: const ['Poland', 'Germany', 'Spain'],
    validator: notNull('Pick a country'),
  );
  final city = AdvancedTextFieldController(validator: filled('Enter a city'));
}

class ConfirmStep extends WizardStep {
  ConfirmStep() {
    registerFields([terms]);
  }

  @override
  String get title => 'Confirm';

  final terms = AdvancedBooleanFieldController<String>(
    validator: (accepted) => accepted ? null : 'You have to accept the terms',
  );
}
```

```dart title="wizard_controller.dart"
/// The wizard owns no fields of its own — every field lives on a step.
/// Which step is on screen is navigation, not form state, so it lives here
/// as a plain field with notifyListeners().
class WizardController extends AdvancedFormController {
  WizardController() {
    steps.forEach(addSubform);
  }

  final account = AccountStep();
  final address = AddressStep();
  final confirm = ConfirmStep();

  late final steps = <WizardStep>[account, address, confirm];

  int get index => _index;
  var _index = 0;

  WizardStep get current => steps[_index];
  bool get isFirst => _index == 0;
  bool get isLast => _index == steps.length - 1;

  /// Validates the current step only, and moves on if it passed.
  Future<bool> next() async {
    final step = current;
    if (!await step.validate()) {
      // Shown its errors once — let it correct itself as the user types. A
      // step's own mode wins over the parent's, so later steps stay quiet.
      step.setValidationMode(ValidationMode.onUserInteraction);
      return false;
    }
    _goTo(_index + 1);
    return true;
  }

  void back() => _goTo(_index - 1);

  /// The parent's validate() reaches every step, including ones already
  /// passed — a value edited on the way back is checked again.
  Future<bool> submit() async {
    if (await validate()) {
      return true;
    }
    // validate() just ran, so canSubmit is an accurate snapshot here.
    final broken = steps.indexWhere((step) => !step.value.canSubmit);
    if (broken != -1) {
      steps[broken].setValidationMode(ValidationMode.onUserInteraction);
      _goTo(broken);
    }
    return false;
  }

  void _goTo(int index) {
    if (index >= 0 && index < steps.length && index != _index) {
      _index = index;
      notifyListeners();
    }
  }
}
```

```dart title="wizard_form.dart"
class WizardForm extends StatefulWidget {
  const WizardForm({super.key});

  @override
  State<WizardForm> createState() => _WizardFormState();
}

class _WizardFormState extends State<WizardForm> {
  final _wizard = WizardController();

  @override
  void dispose() {
    _wizard.dispose();
    super.dispose();
  }

  Future<void> _submit() async {
    final done = await _wizard.submit();
    if (mounted) {
      ExampleLog.of(
        context,
      ).add(done ? 'Account created.' : 'Some steps need fixing.');
    }
  }

  @override
  Widget build(BuildContext context) {
    return ListenableBuilder(
      listenable: _wizard,
      builder: (context, _) {
        final step = _wizard.current;
        return Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            Text(
              'Step ${_wizard.index + 1} of ${_wizard.steps.length} — '
              '${step.title}',
              style: Theme.of(context).textTheme.titleMedium,
            ),
            const SizedBox(height: 8),
            LinearProgressIndicator(
              value: (_wizard.index + 1) / _wizard.steps.length,
            ),
            const SizedBox(height: 12),
            switch (step) {
              final AccountStep step => Column(
                children: [
                  DocsTextField(field: step.email, label: 'Email'),
                  DocsTextField(
                    field: step.password,
                    label: 'Password',
                    obscureText: true,
                  ),
                ],
              ),
              final AddressStep step => Column(
                children: [
                  DocsDropdownField(field: step.country, label: 'Country'),
                  DocsTextField(field: step.city, label: 'City'),
                ],
              ),
              final ConfirmStep step => DocsSwitchField(
                field: step.terms,
                label: 'I accept the terms',
              ),
              _ => const SizedBox.shrink(),
            },
            DocsActions(
              children: [
                if (!_wizard.isFirst)
                  TextButton(
                    onPressed: _wizard.back,
                    child: const Text('Back'),
                  ),
                if (_wizard.isLast)
                  DocsSubmitButton(
                    form: _wizard,
                    label: 'Create account',
                    onPressed: _submit,
                  )
                else
                  DocsSubmitButton(
                    form: step,
                    label: 'Next',
                    onPressed: _wizard.next,
                  ),
              ],
            ),
          ],
        );
      },
    );
  }
}
```

Three decisions in that code are worth keeping:

- **Create the wizard controller above the pages.** A controller built inside a step page dies with it, taking that
  step's values and errors along. With routes, provide it above the `Navigator` or hand it to each route with
  `ChangeNotifierProvider.value`.
- **Escalate the failed step, not the whole form.** After a failed `next()`, the step gets
  `ValidationMode.onUserInteraction` so it corrects itself as the user types. Because a subform's own mode wins over the
  parent's, the steps ahead stay in `manual` and never flag an untouched field.
- **A conditional step stays attached with `setValidationEnabled(false)`.** The example app's *Step Form* screen has an
  invoice step that a switch on the address step adds or drops through `addRelation`. Switched off, the step leaves
  the flow *and* `validate()`, `canSubmit` and `validating`, so one flag is the whole condition — and its values survive
  in case the user flips the switch back.

## Swapping one section for another

A type selector that swaps the active section — a *person* or a *company* — is `removeSubform` of one and
`addSubform` of the other, reacting to the selector field with `addRelation`. Only the attached section takes part in
validation; the detached one keeps its values in case the user switches back, and both are disposed with the parent.
The example app's *Complex Form* screen is this pattern.
