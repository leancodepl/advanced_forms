The four modes cover most forms: validate on submit, on every keystroke, when a field is left, or live once it was
first left. When a form needs a rule none of them states, extend `CustomValidationMode`, override one method, and the
package treats the result exactly like a built-in mode: set it on the form, it reaches every field and subform; set it
on one field, that field keeps it.

```dart
// Re-check a field on its own edits only, never because another field changed.
final class OnOwnEdits extends CustomValidationMode {
  const OnOwnEdits();

  @override
  ValidationAction decide(ValidationContext c) => c.event == ValidationEvent.valueChanged
      ? ValidationAction.full
      : ValidationAction.none;
}

final form = AdvancedFormController(validationMode: const OnOwnEdits());
```

Reach for the built-in modes first. A custom mode is for the case you can state in one sentence and no mode covers,
not for tuning a mode that almost fits.

## What the rule sees

`decide` gets a `ValidationContext`: what is happening now, and three facts about what happened before.

| Field | Meaning |
| --- | --- |
| `event` | What is happening: `valueChanged` (the user edited the value), `unfocus` (focus left the field) or `dependencyChanged` (a field this one depends on changed) |
| `everUnfocused` | The user has left this field after editing it, at least once since `reset()` |
| `everValidated` | `validate()` ran on this field at least once since `reset()`. A form's `validate()` counts for each of its fields |
| `lastStatus` | How the last **finished** check ended: `valid`, `invalid` or `failedValidation`. Null until a check finishes; `clearErrors()`, `prefill()` and `reset()` drop it |

That is the whole input, and the last row is the careful one. The context never carries the live status or the errors.
Every edit clears the errors and a debounced async check sets the status to `pending`, so a rule that asked "does this
field have an error right now" would stop validating at the exact moment the user started fixing the value.
`lastStatus` is immune to that: an edit keeps it, a round in flight does not touch it, and only a check that finishes
replaces it. Do not work around the rest by capturing the field in the class and reading its state from there: that
is the same trap with extra steps.

The four modes are written with the same inputs. `afterFirstUnfocus` is `c.everUnfocused ? onUserInteraction : onUnfocus`.

## What the rule answers

`decide` returns a `ValidationAction`, which is what the field runs:

| Action | What runs |
| --- | --- |
| `none` | Nothing. An edit still clears the errors, because they described the old value |
| `sync` | The sync validator only |
| `full` | The sync validator, then the async one if sync passed. After an edit the async check waits out its debounce; after an unfocus it runs at once |

The built-in modes answer `sync` to a dependency change, because the field's own value did not change and its async
verdict still stands. Your rule may answer `full` there if it needs to.

## What still holds

A custom mode changes which events validate a field and how much runs. It changes nothing else:

- **An untouched field validates nothing on its own.** The field checks that before it asks any mode, so a rule that
  always answers `full` still cannot reach a field the user has not edited. `validate()` is what checks those.
- **`validate()` ignores the mode** and never changes it, custom or not. It does set `everValidated`.
- **Sync runs before async**, and async only if sync passed. There is no action that skips the sync validator.
- **The mode reaches the whole tree.** Set on the form, it is broadcast to every field and subform, including ones
  registered or attached later. A field or subform with its own mode keeps it, as with the built-in modes (see
  [Configuring the mode](./configuring.mdx)).
- **Switching validation off** still beats every mode: `setValidationEnabled(false)` makes the tree behave as `manual`.

## Identity

Modes compare by type: two `OnOwnEdits()` are the same mode, so one created in `build()` is not a mode change and
leaves a round in flight alone. A mode with settings lists them in `props`, so two instances with different settings
are different modes:

```dart
final class LiveOn extends CustomValidationMode {
  const LiveOn(this.events);
  final Set<ValidationEvent> events;

  @override
  ValidationAction decide(ValidationContext c) =>
      events.contains(c.event) ? ValidationAction.full : ValidationAction.none;

  @override
  List<Object?> get props => [events];
}
```

One instance of a mode is shared by every field it reaches, so a mode keeps no state of its own. Everything it knows
about a field is in the context.

## Examples

Re-check a field only when another field changes, never on its own edits. A "repeat password" field that should go
red when the password above it changes, but stay quiet while it is being typed:

```dart
final class FollowsDependency extends CustomValidationMode {
  const FollowsDependency();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.event == ValidationEvent.dependencyChanged ? ValidationAction.sync : ValidationAction.none;
}

repeatPassword
  ..setValidationMode(const FollowsDependency())
  ..subscribeToFields([password]);
```

The format on every keystroke, the server only when the field is left. A username with an async availability check:

```dart
final class SyncLiveAsyncOnLeave extends CustomValidationMode {
  const SyncLiveAsyncOnLeave();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.event == ValidationEvent.unfocus ? ValidationAction.full : ValidationAction.sync;
}
```

Quiet while typing until a check finds an error, live while the user fixes it, quiet again once a check passes:

```dart
final class LiveWhileInvalid extends CustomValidationMode {
  const LiveWhileInvalid();

  @override
  ValidationAction decide(ValidationContext c) => switch (c.event) {
        ValidationEvent.valueChanged => c.lastStatus == FieldStatus.invalid
            ? ValidationAction.full
            : ValidationAction.none,
        ValidationEvent.unfocus => ValidationAction.full,
        ValidationEvent.dependencyChanged => ValidationAction.sync,
      };
}
```

Quiet until the first submit, live after it:

```dart
final class LiveAfterSubmit extends CustomValidationMode {
  const LiveAfterSubmit();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.everValidated ? ValidationMode.onUserInteraction.decide(c) : ValidationAction.none;
}
```

## Try it

Three rules on the Repeat password field; Password stays on the form's default. Type in both fields, then change
Password and watch what each rule does with the mismatch.

```dart title="password_form_controller.dart"
class PasswordFormController extends AdvancedFormController {
  PasswordFormController() {
    registerFields([password, repeatPassword]);
    repeatPassword.subscribeToFields([password]);
  }

  final password = AdvancedTextFieldController(
    validator: atLeastLength(4, 'At least 4 characters'),
  );

  late final repeatPassword = AdvancedTextFieldController(
    validator: (value) =>
        value == password.fieldValue ? null : 'Passwords do not match',
```

```dart title="custom_modes_demo.dart"
// Re-check only when Password changes, never on this field's own edits.
final class FollowsDependency extends CustomValidationMode {
  const FollowsDependency();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.event == ValidationEvent.dependencyChanged
      ? ValidationAction.sync
      : ValidationAction.none;
}

// Re-check on every keystroke, never because Password changed.
final class OnOwnEdits extends CustomValidationMode {
  const OnOwnEdits();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.event == ValidationEvent.valueChanged
      ? ValidationAction.full
      : ValidationAction.none;
}

// Only leaving the field validates it.
final class OnUnfocusOnly extends CustomValidationMode {
  const OnUnfocusOnly();

  @override
  ValidationAction decide(ValidationContext c) =>
      c.event == ValidationEvent.unfocus
      ? ValidationAction.full
      : ValidationAction.none;
}

class CustomModesDemo extends StatefulWidget {
  const CustomModesDemo({super.key});

  @override
  State<CustomModesDemo> createState() => _CustomModesDemoState();
}

class _CustomModesDemoState extends State<CustomModesDemo> {
  final _form = PasswordFormController();
  ValidationMode _rule = const FollowsDependency();

  @override
  void initState() {
    super.initState();
    _form.repeatPassword.setValidationMode(_rule);
  }

  @override
  void dispose() {
    _form.dispose();
    super.dispose();
  }

  void _setRule(ValidationMode rule) {
    setState(() => _rule = rule);
    // The rule is a mode like any other; this field keeps its own.
    _form.repeatPassword.setValidationMode(rule);
  }

  Future<void> _submit() async {
    final ok = await _form.validate();
    if (mounted) {
      ExampleLog.of(context).add(ok ? 'Saved.' : 'Not saved: invalid.');
    }
  }

  @override
  Widget build(BuildContext context) {
    final hint = switch (_rule) {
      FollowsDependency() =>
        'Repeat password re-checks only when Password changes. Its own '
            'edits stay quiet until Save.',
      OnOwnEdits() =>
        'Every keystroke in Repeat password re-checks it. Changing Password '
            'does not.',
      _ => 'Leaving Repeat password validates it. Changing Password does not.',
    };

    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        DocsModePicker(
          title: 'Select your validation mode',
          options: const [FollowsDependency(), OnOwnEdits(), OnUnfocusOnly()],
          selected: _rule,
          label: (rule) => switch (rule) {
            FollowsDependency() => 'followsDependency',
            OnOwnEdits() => 'onOwnEdits',
            _ => 'onUnfocusOnly',
          },
          onSelected: _setRule,
        ),
        const SizedBox(height: 8),
        DocsHint(hint),
        DocsTextField(field: _form.password, label: 'Password'),
        DocsTextField(field: _form.repeatPassword, label: 'Repeat password'),
        DocsActions(
          children: [
            DocsSubmitButton(form: _form, label: 'Save', onPressed: _submit),
            TextButton(onPressed: _form.resetAll, child: const Text('Reset')),
          ],
        ),
      ],
    );
  }
}
```

## Testing a rule

`decide` is a plain method, so test it without a form:

```dart
test('OnOwnEdits ignores dependency changes', () {
  const context = ValidationContext(
    event: ValidationEvent.dependencyChanged,
    everUnfocused: true,
  );
  expect(const OnOwnEdits().decide(context), ValidationAction.none);
});
```

To test it through a field, edit the field first (`setValue`), then drive the event: `setValue` again for
`valueChanged`, `handleUnfocus()` for `unfocus`, `revalidateSync()` for `dependencyChanged`. See
[Testing](../testing.mdx).
